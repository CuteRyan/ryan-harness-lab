# Humanize Korean

사용자가 `/humanize`를 요청했을 때만 실행합니다. 일반 문서 작성이나 긴 답변 뒤에 자동으로 실행하지 않습니다.

## 공통 기준

- 사실, 주장, 수치, 날짜, 고유명사, 인용문은 바꾸지 않습니다.
- 가능성, 추정, 의무의 강도와 과거·현재·미래 시제를 바꾸지 않습니다.
- 부정, 조건, 인과관계와 목록·표·제목 구조를 유지합니다.
- 글의 목적, 말투, 독자층을 유지합니다.
- 익숙한 기술 용어를 억지로 번역하거나 새로운 한국어 명칭을 만들지 않습니다.
- 이미 자연스러운 부분은 그대로 둡니다.
- 변경률이 30%를 넘으면 이유를 알리고, 50%를 넘으면 중단합니다.
- 확신하기 어려운 수정은 적용하지 않고 결과 메모에 남깁니다.

## 기본 모드

현재 Claude 세션이 직접 처리합니다. 에이전트, 팀, 별도 검토 작업을 호출하지 않습니다.

1. 사용자 메시지의 원문과 `references/quick-rules.md`를 읽습니다.
2. 수정이 필요한 부분만 다듬습니다. 이미 자연스러우면 그대로 둡니다.
3. 원문과 결과를 한 번 비교해 공통 기준이 지켜졌는지 확인합니다.
4. 문제가 있으면 해당 부분만 한 번 고칩니다. 반복 검토는 하지 않습니다.

결과는 채팅에 다음 순서로 바로 반환합니다.

1. 변경률과 보존 확인 한 줄
2. 다듬은 본문
3. 주요 변경과 남은 문제를 포함한 짧은 요약

기본 모드에서는 실행 폴더를 찾거나 파일을 만들지 않습니다. 사용자가 파일 저장을 명시적으로 요청한 경우에만 현재 작업 폴더에 `_workspace/{YYYY-MM-DD-NNN}/`를 만들고 `01_input.txt`, `final.md`, `summary.md`를 저장합니다.

기본 모드에서는 다른 기준 파일을 읽거나 추가 보고서를 만들지 않습니다.

## 정밀 모드

사용자가 `--strict` 또는 "정밀 검토"를 요청했을 때만 사용합니다. 긴 글이라는 이유만으로 자동 전환하지 않습니다.

현재 작업 폴더에 `_workspace/{YYYY-MM-DD-NNN}/`를 만들고 입력을 `01_input.txt`로 저장합니다. 같은 날짜의 마지막 번호 다음 값을 사용합니다.

1. `ai-tell-detector` → `02_detection.json`
2. `korean-style-rewriter` → `03_rewrite.md`, `03_rewrite_diff.json`
3. `content-fidelity-auditor` → `04_fidelity_audit.json`
4. `naturalness-reviewer` → `05_naturalness_review.json`
5. 두 검토 결과가 통과하면 `final.md`와 `summary.md` 작성

독립 검토를 동시에 실행할 수 있으면 병렬로 실행하되, 특정 팀 도구나 모델을 강제하지 않습니다.

## 재작업

- 내용 보존 실패: 문제가 된 변경만 되돌리고 다시 수정
- 자연스러움 부족: 지적된 부분만 한 번 더 수정
- 최대 3회에도 해결되지 않음: 작업을 멈추고 남은 문제를 보고
- "이 문단만", "수정 정도 조정", "한 번 더 다듬기": 지정 범위만 다시 실행

## 실행 규칙과 연구 자료

- 기본 모드는 `references/quick-rules.md`만 읽습니다.
- 정밀 모드도 같은 파일을 최우선 기준으로 사용합니다.
- 정밀 모드에서 판단이 애매할 때만 `references/ai-tell-taxonomy.md` 또는 `references/rewriting-playbook.md`의 관련 항목을 찾아봅니다. 두 파일 전체를 자동으로 읽지 않습니다.
- `references/scholarship.md`, 메트릭, 기준값 파일은 연구와 규칙 관리용이며 일반 글 다듬기에는 사용하지 않습니다.

상세 자료의 처방이 공통 기준과 충돌하면 적용하지 않습니다.
