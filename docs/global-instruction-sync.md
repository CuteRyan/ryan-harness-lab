# 클로드·코덱스 글로벌 지침 동기화

## 결론

2026-09-12부터 글로벌 지침의 편집 원본은 [global-instructions.md](../settings/global-instructions.md) 하나다.
두 도구에서 같게 적용할 수 있는 표현으로 기존 차이를 통합했다. 도구별 실행 설정은 통합하지 않았다.

공통 규칙 수정 후 저장소 루트에서 다음 명령을 실행한다.

```powershell
python scripts/sync-global-instructions.py
python scripts/sync-global-instructions.py --check
```

첫 명령은 양쪽 지침을 함께 갱신하고 되읽어 검증한다. 두 번째 명령은 변경 없이 일치 여부만 확인하며, 불일치하면 실패로 끝난다.
파일을 저장할 때 자동 실행되는 감시 작업은 아니다. 지침을 수정한 에이전트가 같은 작업 안에서 이 명령을 실행한다.

## 변경과 이유

| 역할 | 위치 |
|---|---|
| 사람이 편집하는 공통 원본 | `settings/global-instructions.md` |
| 저장소의 생성본 | `settings/AGENTS.global.md`, `settings/CLAUDE.global.md` |
| 로컬 코덱스 지침 | `~/.codex/AGENTS.md` |
| 로컬 클로드 지침 | `~/.claude/CLAUDE.md` |

기존 두 원본을 따로 고치는 방식은 공통 규칙이 서로 달라질 수 있었다. 이제 [동기화 코드](../scripts/sync-global-instructions.py)가 원본 하나에서 네 생성본을 만든다. 같은 본문과 짧은 생성 안내를 사용하며, 전체 내용을 비교한다. 유지할 것은 공통 원본, 대상 경로 네 개, 동기화 코드와 테스트다.

생성본에 별도 수정을 발견하면 어느 파일도 쓰기 전에 중단한다. 해당 변경을 읽어 필요한 내용을 원본에 통합하고 생성본의 별도 변경을 정리한 뒤 다시 실행한다. 손으로 작성한 기존 파일은 자동으로 생성본으로 전환하지 않는다. 이번 최초 전환은 기존 네 파일을 비교하고 확인한 내용을 패치로 통합한 후 수행했다.

파일별 교체는 임시 파일을 이용한다. 반영 중 예외가 나면 이미 반영한 파일을 이전 내용으로 되돌린다. 별도 백업 파일은 남기지 않으며, 사용자 설정 파일에는 접근하지 않는다. 여러 파일 전체가 운영체제 수준에서 한 번에 교체되는 것은 아니므로 프로세스 강제 종료 등으로 중단됐다면 `--check` 후 재실행한다.

주인님이 강조한 **브리지 코드와 프롬프트의 책임 구분**은 공통 원본의 [Harness 항목](../settings/global-instructions.md#harness)에 반영했다. 후속 지적에 따라 모호한 “코드로 처리”를 “브리지의 실제 처리 로직”으로 명확히 하고, 기존 네 대원칙이 브리지 로직과 그 안의 프롬프트에도 적용됨을 밝혔다. 실행 계층이 맡을 일과 해석·판단에 필요한 문서를 구분한다. 이 문서가 규칙의 별도 원본은 아니다.

## 검증

2026-09-13: 글로벌 시작 문서 목록에 누락된 개인 메모리 인덱스를 추가하고 [공통 메모리 정책](agent-structure.md#memory)에 연결했다. 아래 검사로 로컬 지침 반영을 확인했으며, 개별 에이전트 구현은 별도 작업이다.

- 원본 수정 후 네 생성본의 갱신·동일성, 두 번째 실행의 무변경, 읽기 전용 검사, 별도 수정과 비관리 파일 보존, 누락 파일 복구, 쓰기 실패 시 복구: [테스트](../tests/test_sync_global_instructions.py) 6개 통과.
- 실제 동기화에서 네 파일을 갱신했고, `--check`가 통과했다.
- Python 기본 오류·포맷 검사와 변경분 공백 검사를 확인했다.
- 이번 적용 범위는 로컬 글로벌 지침이다. VPS 지침, 사용자별 설정, 스파이더맨 배포본은 변경하지 않았다. 이미 실행 중인 세션이 파일 변경을 다시 읽는지는 이번 검증에 포함하지 않았다.
