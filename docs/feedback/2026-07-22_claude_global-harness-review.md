# Claude 검토: 글로벌 하네스 경량화

## 범위와 한계

Claude Sonnet에 오늘 완료 보고를 전달해 설계 수준 검토를 받았다. CLI의 읽기 전용 파일 탐색은 세 차례 120초 제한을 넘어, 실제 파일 줄 단위 검토 대신 변경 내용·수치·검증 결과를 담은 완료 보고를 검토했다. 파일 근거는 이후 Codex가 직접 대조했다.

## Claude 지적 요약

1. **높음 — Bash 훅 분기 테스트 부족**: `git reset --hard`, 강제 push, 일반 push와 연결 명령의 통합 경로 검증이 부족하다고 지적했다.
2. **높음 — 운영 settings 참조 확인 누락**: 삭제된 훅을 운영 `settings.json`이 계속 참조할 가능성을 지적했다.
3. **중간 — Git 밖 문서의 복구 수단**: 자동 백업 중단으로 Git 밖 문서의 복구 수단이 약해질 수 있다고 지적했다.
4. **중간 — humanize 실행 검증 부족**: 대폭 줄인 프롬프트가 실제 출력 파일을 만드는지 실행하지 않았다고 지적했다.

## 실제 파일 대조

### 1. 반영

`git push --force`는 차단됐지만 축약형 `git push -f`와 연결된 `git push -f`가 통과하는 결함을 재현했다. 두 훅의 정규식을 수정하고 통합 훅 테스트 6건을 추가했다.

- 일반 push 허용
- `-f` 차단
- `--force-with-lease` 차단
- 연결 명령의 `-f` 차단
- `reset --hard` 차단
- 문서 redirect 차단

전체 훅 테스트 19건이 통과했고 글로벌 운영본에서도 `git push -f`가 `exit 1`로 차단됐다.

### 2. 반박

운영 `settings.json`은 `pre-bash-guards.sh`와 `doc-protection.sh` 두 개만 참조한다. 삭제된 훅·규칙·보조 파일의 활성 참조를 다시 검색했으며 확인된 참조는 없었다.

### 3. 위험을 알고 유지

Git 밖 문서에 자동 백업을 다시 적용하면 모든 Edit 지연과 백업 누적 문제가 돌아온다. 일반 편집은 Git 또는 편집기 이력을 사용하고, 대량 덮어쓰기처럼 복구하기 어려운 작업은 사전 확인한다는 현재 기준을 유지한다.

### 4. 보류

humanize는 frontmatter와 출력 파일 계약만 확인했고 실제 모델 실행은 하지 않았다. 비용이 드는 동작 검증이므로 이번 작업에서는 보류하며, 다음 실제 `/humanize` 요청을 첫 실행 확인으로 삼는다.

## 결론

Claude 지적 4건 중 1건 반영, 1건 반박, 1건 위험 수용, 1건 실행 확인 보류다. 반영한 강제 push 결함은 테스트와 글로벌 동기화까지 완료했다.
