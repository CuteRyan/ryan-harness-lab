# 2026-09-20 — 전역 훅의 삭제 확인 제거

- 결론: `pretooluse-guard.ps1`에서 대량 삭제(`rm -rf`, `rm -f`, 와일드카드, `find -delete`, `shred` 등) 확인 요청을 뺐다. 전역 훅은 [훅 정책](../hook-policy.md)대로 되돌릴 수 없는 Git 명령만 막는다.
- 이유: 훅의 `ask` 응답은 권한 건너뛰기 모드에서도 확인 창을 띄운다. 지난 대화 기록에서 218번 떴고(`rm -f` 143번, `rm -rf` 75번), 대상은 대부분 임시 폴더와 서버의 옛 배포 폴더였다. 이 기능은 정책 문서에 없었고 테스트도 없었다. Bash에만 걸려 있어 PowerShell 도구나 파이썬 삭제는 통과했다. 되돌리기 어려운 삭제 전 확인은 글로벌 지침에 따라 모델이 판단한다.
- 변경: 삭제 판정 함수 두 개와 호출부를 제거했다. `tests/test_pretooluse_guard.ps1`에 삭제 명령 4종이 확인 없이 통과하는지 보는 검사를 추가했다. 운영본 `~/.claude/hooks/`에 복사했고, 이전 파일은 `~/.claude/hooks/.backups/pretooluse-guard.ps1.20260920-before-delete-removal`에 두었다.
- 검증: 훅 테스트 전체 통과. 새 삭제 검사는 이전 훅에서는 `ask`를 출력해 실패한다. 원본과 운영본 SHA-256 일치(`08a16483…`). 운영 훅에서 `rm -rf`는 조용히 통과하고 `git reset --hard`, `git -C . clean -fd`는 종료 코드 2로 막힌다. 이 세션의 Bash 도구에서 `rm -rf`가 확인 창 없이 실행됐다.

## 설치 스크립트의 훅 등록 형식 수정

- 결론: `scripts/install-global-hook.ps1`이 훅을 `-File` 형식으로 등록하도록 고쳤다.
- 이유: 예전 스크립트는 `-Command "& '...'"` 형식으로 등록했다. 이 형식은 차단 신호인 종료 코드 2를 1로 바꾸고, Claude Code는 1을 차단으로 보지 않는다(커밋 `0f14ebe` 참고). 운영 설정은 이미 `-File` 형식이었지만, 스크립트를 다시 실행하면 Git 차단이 조용히 풀릴 수 있었다.
- 변경: 설치 테스트가 설치된 훅 명령을 실제로 실행해 `git reset --hard`에서 종료 코드 2가 나오는지 확인한다. 훅 테스트의 stdin 검사도 예전 형식에서 1을 기대하던 것을 `-File` 형식에서 2를 기대하도록 바꿨다.
- 검증: 두 테스트 모두 통과했다. 예전 설치 스크립트로 돌리면 새 설치 테스트가 "got 1"로 실패한다. 운영 설정의 등록 문자열은 새 스크립트가 만드는 문자열과 같아서 다시 설치하지 않았다.
