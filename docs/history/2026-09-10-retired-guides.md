# 글로벌 하네스의 구형 절차와 메모리 정리

- 결론: 현재 글로벌 지침 2개와 Claude 규칙 8개는 원본·운영본이 같았다. 이를 다시 늘리지 않고, 옛 절차를 재주입하는 가이드·템플릿·스킬과 낡은 메모리를 정리했다.
- 변경: 개발·문서 워크플로 안내는 합계 439줄에서 10줄로, CLAUDE 템플릿은 63줄에서 11줄로, `claude-md` 스킬은 79줄에서 35줄로 줄였다. 특정 문구·길이·섹션·체크리스트 승인·전체 기록 import 강제를 제거했다. 실제 프로젝트 사실에 근거한 작성, 기존 수정 보존, 읽기 전용 감사를 유지했다.
- 변경: 원본·활성 메모리의 사라진 프로젝트 경로와 중복 목록을 정리하고 PA 현재 경로를 반영했다. 활성 사본에만 있던 사용자·Telegram 자료 연결은 보존했다. 과거 VPS 이전 표는 현재 상태로 사용하지 않도록 원본 기록에 연결했다. 메모리 두 인덱스는 용도가 달라 서로 덮어쓰지 않았다.
- 보존: 이전 가이드·템플릿·스킬 4개와 메모리 3개는 `docs/archive/2026-09-10-retired-guides/`에 바이트 그대로 보관했다. `claude-md` 운영 사본은 교체 전 기존 원본과 일치를 확인하고 원본에서 복사한 뒤 SHA-256 일치를 검증했다. 사용자 설정·전역 훅·기존 미커밋 변경은 보존했다.
- 검증: 현행 링크와 메모리 참조, YAML·Claude 메타데이터, diff 검사를 통과했다. Codex 스킬 검사기는 기존 Claude 전용 frontmatter를 지원하지 않아 통과하지 못했으며, 해당 키를 보존하고 별도로 검증했다. 실행 코드 변경은 없다. 정리 완료 당시 커밋·push·VPS 변경은 하지 않았다.
- 독립 검토: 임시 프로젝트에서 init 지침을 적용해 실제 코드·설정에 근거한 짧은 문서를 만들고 안내한 테스트 1개를 통과했다. audit에서는 없는 경로를 찾아 보고하고 사용자 수정 파일의 전후 해시가 같음을 확인했다. 스킬 지침을 직접 적용한 검토이며 자동 호출기를 시험한 것은 아니다. 최종 문서·메모리 연결 70개와 원본·운영본 11쌍도 확인했다.
- 로컬 기록: 사용자 승인에 따라 9월 9~10일의 지침·규칙·문서·스킬 정리를 함께 커밋한다. 기존 `skills/handoff/SKILL.md` 변경은 제외한다. `memory/`는 저장소가 명시적으로 무시하므로 정리된 원본 메모리는 로컬에 유지하고 강제 추가하지 않는다. 보관 문서에는 인증정보 본문이 없음을 확인했다. push·VPS 변경은 하지 않는다.
