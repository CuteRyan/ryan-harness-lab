# SSOT 즉시 동기화 (글로벌)

**핵심**: 주인님 SSOT 결정은 즉시 **메모리 + docs/design + 코드 3축 동시 동기화**. 결정-박제 시차 0. 결정만 하고 박제 안 하면 다음 사이클이 옛 SSOT 끌어씀 → 결과 폐기·비용 손실.

## 의무 조건 (하나라도 해당 시)
- 코드 어휘 변경 (변수·함수·라벨·시민 LLM 노출 텍스트)
- 도구·필드·인자 추가/제거
- 후보·정당·인구 데이터 변경
- 라운드/단계 분배 결정
- 사용자 노출 텍스트 (시스템 프롬프트·도구 description) 변경
- 도구 인자/출력 형식 갱신

## 3축 동기화 (모두 같은 사이클에)
1. **메모리** — 관련 메모리 본문 + frontmatter + `MEMORY.md` 인덱스. 옛 표기 폐기 명시 + 신 SSOT 박제
2. **docs/design** — 옛 표기 deprecated 마킹 + 신 표기 추가 (시점 스냅샷 보존)
3. **코드** — 함수·상수·테스트·주석 정합 + Streamlit `views/*` 동기

## 예외 (박제 면제)
단발성 실험(스모크·테스트) · 임시 진단 스크립트(`_*.py`) · 시점 스냅샷(`.bak`/`[ARCHIVED]`) · 주인님 소유 영역(`docs/thesis/*` 등, 보고만)

## 절차 (결정 직후)
1. 결정 인지 → SSOT 후보 식별 (어떤 영역 영향?)
2. 3축 동시 Edit (분리 금지)
3. 검증 — `Grep` 옛 표기 잔존 0 + 관련 테스트(`make check`·pytest) 통과
